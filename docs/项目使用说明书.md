# K-Swap 项目使用说明书

## 项目简介

K-Swap 是部署在 Solana devnet 的恒定乘积 AMM。它支持外部钱包创建一组 SPL Token 池、注入初始流动性，以及按 `x*y=k` 执行双向 exact-in swap。当前版本不铸造 LP Token，也不支持后续增减流动性；这是明确的演示范围。

## 架构与目录

- `program/src/lib.rs`：Pinocchio 链上程序、账户验证、SPL Token CPI 和定价公式。
- `dapp/app`：Next.js App Router 页面、钱包连接、模拟与交易反馈。
- `dapp/lib/amm.ts`：与 ABI 一致的编码器、PDA 推导和报价函数。
- `docs/ABI.md`：完整二进制接口。

## 环境与安装

需要 Rust、Solana CLI（含 `cargo-build-sbf`）、Node.js 20+、npm 与浏览器钱包。若使用命令行创建测试 Token，还需随 Solana 工具链安装的 `spl-token` CLI。网络必须为 devnet：

```bash
solana config set --url devnet
solana config get
cd dapp
npm ci
cp .env.example .env.local
npm run dev
```

打开 `http://localhost:3000`，并将钱包切换到 devnet。默认 RPC 是 `https://api.devnet.solana.com`。

启动前建议核验 CLI 网络与钱包；输出中的 RPC URL 必须是 devnet，且地址与余额应可正常读取：

```bash
solana config get
solana address
solana balance --url devnet
```

浏览器钱包与 Solana CLI 钱包可以是不同地址。页面交易只由浏览器中当前连接的钱包授权，不会读取 CLI keypair。公共 RPC 可能限流，可在 `dapp/.env.local` 设置：

```dotenv
NEXT_PUBLIC_SOLANA_RPC_URL=https://api.devnet.solana.com
```

## 页面操作

### 创建池

连接钱包，选择“创建池”，填写两种不同的经典 SPL Token mint、两边初始数量（最小单位）和手续费 bps。页面在一个原子交易中创建 vault ATA、初始化 Pool PDA 并转入初始储备。一个 owner 钱包当前只能有一个池；owner 就是调用初始化的钱包。

### Swap

选择“Swap”，按 A→B 顺序填写 mint、输入最小单位数量和滑点。客户端读取实时 vault 储备计算 `minimum_amount_out`，先模拟，成功后才请求钱包签名。反向交换可点击中间的方向按钮。确认后页面提供 devnet 浏览器链接。

### 测试 Token

#### 创建 SPL Token

1. 连接已切换到 devnet 的浏览器钱包，并确保钱包有少量 devnet SOL。
2. 选择“测试 Token”→“创建 SPL Token”。
3. 输入 Token Name（最多 32 UTF-8 字节）、Symbol（最多 10 UTF-8 字节）、可选的 `https://`/`ipfs://` Metadata URI（最多 200 UTF-8 字节），以及 `0..=9` 的小数位。URI 应指向符合 Metaplex JSON 约定的公开元数据文件；留空时仍会创建包含名称和 Symbol 的链上 metadata 账户。
4. 点击“创建测试 Token”。客户端生成临时 mint keypair，查询 mint 账户免租余额，并在同一原子交易中创建/初始化 mint 和 Metaplex Token Metadata PDA；交易先模拟再请求钱包签名。
5. 交易确认后复制“最近创建的 mint”地址，或点击地址进入 devnet Explorer。

新 mint 使用经典 SPL Token Program `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA`，元数据由 Metaplex Token Metadata Program `metaqbxxUerdq28cj1RbAWkYQm3ybzjb6a8bt518x1s` 管理。连接钱包同时成为 mint authority、freeze authority 和 metadata update authority；临时 mint 私钥只用于签署创建交易，不写入浏览器存储、日志或仓库。

#### Mint Token

1. 选择“测试 Token”→“Mint Token”。
2. 填入经典 SPL Token mint 地址。当前连接钱包必须是该 mint 的 mint authority。
3. 输入要增发的**最小单位整数**。例如 decimals 为 6 时，输入 `1000000` 表示 1 个展示单位；输入 `2500000` 表示 2.5 个展示单位。
4. 点击“增发到当前钱包”。客户端推导当前钱包的 ATA；若 ATA 不存在，会把创建 ATA 与 `MintTo` 放入同一原子交易。
5. 钱包签名并确认后，通过页面交易链接检查指令与状态。

两项操作均先模拟、再请求钱包签名，仅用于 devnet 测试资产。

#### CLI 等价操作

以下命令使用当前 Solana CLI 钱包，与浏览器钱包互不共享密钥。先确认 CLI 指向 devnet，再执行：

```bash
solana config set --url devnet
spl-token create-token --decimals 9
spl-token create-account <MINT_ADDRESS>
spl-token mint <MINT_ADDRESS> 1
spl-token balance <MINT_ADDRESS>
```

`spl-token mint` 默认接收展示单位，而页面输入最小单位；例如 9 位小数时，CLI 的 `1` 对应页面的 `1000000000`。不要把示例中的占位符原样执行。

#### 链上核验

```bash
spl-token display <MINT_ADDRESS> --url devnet
spl-token accounts --owner <WALLET_ADDRESS> --url devnet
solana confirm <TRANSACTION_SIGNATURE> --url devnet
```

也可访问 `https://explorer.solana.com/address/<MINT_ADDRESS>?cluster=devnet`。核验 mint authority、decimals、supply、钱包 ATA 与 Token balance 是否符合预期。

## 参数与账户

精确字节布局、账户顺序、权限和错误码见 `docs/ABI.md`。客户端不得自行更换 Token Program，合约仅接受经典 SPL Token Program；Token-2022 不在当前范围。

测试 Token 工具直接调用 System Program、Associated Token Account Program、经典 SPL Token Program 与 Metaplex Token Metadata Program，不经过 K-Swap Program，因此不属于 K-Swap 自定义 ABI。创建 mint 的 payer、mint/freeze authority、metadata update authority 均为连接钱包；Mint Token 的 authority 和 ATA owner 也均为连接钱包。Metadata PDA seeds 为 `["metadata", Token Metadata Program ID, mint]`。

```bash
NO_DNA=1 cargo fmt --check
NO_DNA=1 cargo clippy --workspace --all-targets
NO_DNA=1 cargo test --workspace
NO_DNA=1 cargo build-sbf --manifest-path program/Cargo.toml
solana program deploy target/deploy/kswap_program.so --program-id program-keypair.json --url devnet

```

`program-keypair.json` 仅用于维护 Program ID，已被 `.gitignore` 排除，绝不能提交或公开。部署必须使用当前 Solana CLI 钱包，且只能选择 devnet。

## 常见错误

- `InvalidPda`：当前钱包已有 Pool，或客户端 PDA seeds 不一致。
- `InvalidMint`：mint 相同、vault authority 不是 Pool PDA，或 vault 与 Pool 记录不匹配。
- `Slippage`：储备在报价后变化，增加合理滑点或刷新后重试。
- `模拟失败`：确认钱包在 devnet、有 SOL 支付租金/手续费，且有足够 Token A/B。
- `owner does not match`：当前钱包不是所填 mint 的 mint authority，无法增发。
- `Invalid public key input`：mint 地址格式错误；从创建结果或 Explorer 重新复制完整地址。
- `insufficient funds`：钱包没有足够 devnet SOL 支付 mint/ATA 租金与手续费；先补充 devnet SOL。
- `IncorrectProgramId`：填入的地址不是经典 SPL Token mint，或使用了当前页面不支持的 Token-2022 mint。
- 钱包看不到余额：确认钱包网络为 devnet，并手动导入 mint；同时通过 Explorer 或 `spl-token accounts` 核验 ATA。
- RPC 限流：在 `.env.local` 配置自己的 devnet RPC。

## 安全说明

程序检查 signer、writable、owner、PDA、账户数量和数据长度，使用 checked u128 算术，并绑定两个 vault。所有交易由用户钱包持有并签名；页面不会读取或上传钱包私钥。创建测试 mint 时浏览器会在内存中生成 mint keypair，并仅用它对当前创建交易做部分签名；刷新页面后无法恢复该 keypair，但 mint authority 仍是用户钱包，因此不影响后续增发。项目未经第三方审计，只可使用 devnet 测试资产。
